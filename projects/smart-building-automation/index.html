ARCHITECTURE LAYER 01 / 04

Field devices

Sensors provide inputs such as occupancy, light level or temperature. Actuators operate the connected equipment. Device selection should reflect the actual function, environment and required response.

Engineering check: device compatibility, location, power requirements, environmental rating and manual override.

Conceptual architecture only. Product protocols, network topology, safety interlocks and control behaviour must be confirmed for the selected equipment and project.

The challenge

Lighting, access, sensors and other connected systems may come from different manufacturers and use different communication methods. Poor integration can create unreliable scenes, confusing controls or a system that is difficult to maintain.

Engineering approach

The work is approached in stages, with design decisions tied to the actual site conditions, equipment data and applicable requirements.

  1. Document the functions users want to automate and the existing electrical constraints.
  2. Choose compatible control devices and define the system architecture before installation.
  3. Plan wiring, network coverage, power supplies and manual override arrangements.
  4. Configure lighting scenes, occupancy responses and approved integrations.
  5. Apply sensible user permissions and secure device configuration.
  6. Test normal operation, failure behaviour and manual control, then provide a clear user handover.

Intended outcome

The intended result is a more convenient and coherent control experience for the selected building functions, with manual operation and maintainability considered from the outset.

Key engineering considerations

Interoperability, network resilience, cybersecurity, privacy, fail-safe behaviour, manual override and future servicing.

Engineering design note

Design basis & verification

The following are typical inputs and checks for this class of system. They are a planning aid, not evidence that a specific site has been surveyed, designed or commissioned.

Design inputs to confirm

  • User requirements, controlled functions, operating modes and priority scenarios
  • Device compatibility, communication protocol, network topology and power requirements
  • Manual override, safe state, loss-of-communications behaviour and recovery expectations
  • Cybersecurity, privacy, access permissions and future maintenance responsibilities

Verification before handover

  • Device addressing, network connectivity and control-sequence verification
  • Manual override, interlocks, alarms and fail-safe behaviour
  • Loss-of-power/network response and recovery after restoration
  • User permissions, handover guidance and maintenance documentation

Final values, protective-device selections, test methods and acceptance criteria must be established from verified site conditions, equipment data and applicable Nigerian requirements and relevant installation standards.
